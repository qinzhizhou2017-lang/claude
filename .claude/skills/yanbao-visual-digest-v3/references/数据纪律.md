# 数据纪律（原样继承 + v3 两条新增）

> 这条线在 9.01 事故里其实是**好的**：178 个数字回查 0 个真错，8 个未命中全是日期格式 / 图表读数 /
> 单位换算的假阴性。失效的是"做什么"，不是"做对没"。**所以一条都不许简化。**

---

## 一、写的时候（五条）

1. **逐份处理**：抽完一份原文就写完那一份，再动下一份。不要全读完再统一写——那会让第一份的原文
   在你动笔时已经离得太远。
2. **每个数字留出处**，HTML 注释四型：
   - `<!--src: MS p24 表-->` 文本层可查
   - `<!--src: MS p24 图/目测-->` 从图上读的
   - `<!--src: MS p24 正文-->` 叙述句
   - `<!--src: 测算 = 88−60=28 kt，据 MS p6 表-->` **（v3 新增）** 自算值，写出算式与来源；
     回查脚本对这型**重算**而不是 grep
3. **推论必须标记**：原文没有、你自己算出来的结论，正文里写"（本文测算）"，不要让它长得像研报观点。
4. **拿不准就说拿不准**：任何一个数字回忆不起确切出处，直接告诉用户，不要补一个看起来合理的。
5. 不要把原文的限用水印邮箱写进产物。

## 二、每份写完立刻自查（不许留到最后）

趁这份原文还在手边，逐条过：

- **A 抄录**：数字、单位、量级（亿/万亿）、同比 vs 环比，有没有写错
- **B 图表读数**：所有标了"目测"的，重新打开那页图核一遍
- **C 归属**：牛市/基准/熊市有没有串；FY 和 CY 有没有混；市场一致预期有没有被写成机构自己的预测；
  观点有没有安错人
- **D 推论**：加的推断是不是都标了"（本文测算）"
- **E 交叉对账（v3 新增）**：分组数字与总盘对得上吗？
  （8.26 实测：制作方自查 + 机器验收全 PASS，仍把"8 买入 1 中性"写成"7 买入"，而 P1 总盘 24 买入
  本可倒推出矛盾。**分组必与总盘对账**。）

**C 类最容易出**，因为数字在原文里确实存在，只是被安到了错的年份、错的情形、错的主语上——
机器 100% 查不出来，只能靠写的时候就记牢。D 类同样查不到。

## 三、全部写完后跑机器回查

把成品里的数字全抽出来 → 去掉逗号和小数点归一化成纯数字串 → grep 抽取的 .txt 正文。

**只把"追不到的"列出来**，逐个说明是哪一种：

- 图表读数（文本层本来就没有，正常）
- 单位换算造成的假阴性（正常）
- 日期格式差异（2Q26 / 2026年二季度，正常）
- **真的对不上**（必须改）

⚠️ **绝对禁止回复"已逐项核对，数据无误"**——那是制造虚假确定性。
直接给待核清单；一条都没有就说「回查 N 个数字，全部追溯到原文，无待核项」。

## 四、原报告自己错了怎么办

实测 10 篇挖出**原报告自身**问题十余处（评级正文与披露页打架、币种 CNY/HKD 标错、日期笔误、
排印错、同一数字正文与表格两套值、Exhibit 重复排印）。

统一处理：**照录原文 + 标存疑 + 绝不替它改数**。在成品里用一行小字注明"原报告此处正文与表格不一致，
此处照录正文"。

## 五、扫描件（无文本层）时的降级方案

实测真实投行研报 **8/10 是纯图片 PDF**。此时：

- 文本抽取与关键词跳免责**全部失效**，`page_map.py` 会直接报错拦住（不吐空文件）
- 必须 `--render all` 转图按页读
- **grep 类回查全部失效**——唯一可靠的替代是隔离交叉验证（另起一个看不到制作过程的核查任务，
  对照原 PDF 逐项核；实测约 12 万 token/篇）
- 批次做完**默认加一轮隔离交叉验证**，它在制作方自查 + 机器验收全 PASS 之后仍抓到过重大事实错误

## 六、隔离与串台

多份同时做时，一篇一个隔离子任务，硬边界"不得引用其他研报"。
实测两篇腾讯研报（JPM HK$690 / 大摩 HK$550）由互不可见的子任务处理，目标价如实保留为两个数，没有串台。
