## 知识库划定的四大技术模块

### 模块 1：Attention 机制
- 是什么：每个 token 与序列中所有 token 计算相关性权重，加权聚合信息
- 为什么强：全局依赖建模，且可并行（对比 RNN 的顺序处理）
- 代价：计算量随序列长度平方增长 O(n²) → 长上下文贵、慢
- 进阶考点：多头注意力 MHA 的作用；推理优化变体 MQA / GQA 为何省显存

### 模块 2：Transformer
- 核心结构：自注意力 + 前馈网络 + 残差连接 + LayerNorm + 位置编码
- 为什么取代 RNN：可并行训练、长依赖处理更好、易于规模化（Scaling）
- 编码器 vs 解码器：编码器双向看全句（理解），解码器只看左侧（生成）
- 产品视角：上下文窗口、token 计费、首字延迟等产品参数的技术根源

### 模块 3：BERT
- 结构：Transformer 编码器堆叠；双向预训练
- 两个预训练任务：掩码语言模型 MLM（完形填空）+ 下一句预测 NSP
- 经典缺陷考点：预训练用 [MASK] 标记、微调时没有 → 训练/使用不一致
- 与 GPT 对比（必考）：BERT 理解型（分类/问答/情感），GPT 生成型
  （写作/翻译/对话）；BERT 小而快，适合线上高并发判别任务

### 模块 4：ChatGPT 原理
- 三步走：预训练（海量文本自监督）→ SFT（指令数据监督微调）→
  RLHF（奖励模型 + 强化学习对齐人类偏好）
- 相比 BERT 时代：模型规模、数据量、训练时长全面放大；
  具备 Few-shot / Zero-shot 能力——不用重训就能干新任务
- 思维链 CoT：推理任务的关键提示技巧

## 面试/汇报时的回答框架（归档者补充）

被问任何技术问题，按三层答：
1. **一句话原理**（它是什么）
2. **产品含义**（它决定了什么产品参数/成本/体验）
3. **取舍判断**（什么场景用它、什么场景不用——例：先 RAG 后微调）
