# R2 深度研究模板（重点方向统一标准）

> 主协调 Agent 编写，v1.0。所有 R2 深度研究稿必须逐项回答下列问题。允许结论为“不成立”“不适合个人进入”或“仅有短期价值”——重点研究不等于推荐。

## 文件要求

- 深度研究稿：`agents/R2/<方向编号>_<方向名>.md`
- 新增来源继续追加到本 Agent 的 `sources/A0X_sources.jsonl`（编号接着 R1 往下编）；新增数据卡追加到 `data/A0X_data.jsonl`。
- 可以直接引用其他 Agent 台账中的来源编号（如 [A05-S012]），但必须先打开对应 jsonl 核对该条内容确实支持你的表述。
- 正文用**可直接进入最终报告的中文连贯论述**，以分析段落为主，比较与数据用表格。正文 4,000–6,000 汉字。不写空话，不重复背景。
- 每个关键判断标注【事实】【推断】【预测】和置信度（高/中/低），并附来源编号。

## 必答结构

```markdown
# <方向编号> <方向名>：深度研究稿
- 负责 Agent：A0X；轮次：R2；完成时间：；本轮新增检索：N 次

## 0. 一句话结论与置信度（≤150 字：成立与否、属于哪类、适合谁）
## 1. 它解决什么问题：因果链
   技术变化 → 原有任务如何变化 → 制造了什么新需求/瓶颈/责任 → 形成什么付费活动 → 支撑什么企业或岗位
## 2. 性质判定：类别（T1–T5，可注次要属性）与新颖度（N0–N3），并说明为什么不是其他类别
## 3. 谁使用、谁付费、谁批准预算；不购买的代价
## 4. 证据：真实公司、产品、招聘岗位、付费案例（表格：主体｜做什么｜证据｜案例状态 C1–C5｜证据等级｜能证明到什么程度）
## 5. 市场规模与需求增长：区分 M1–M5；如需估算，公开公式、参数、区间与依据（用 python3 计算并给出过程）
## 6. 收费方式、交付方式、成本结构与单位经济
## 7. 个人或小团队可切入的具体环节：所需技能（学到什么程度）、行业资源、资金、时间
## 8. 进入者优势的来源（技术/行业知识/客户关系/数据/组织能力/责任承担）及其可持续性
## 9. 替代风险：下一代模型、标准化产品、大平台吸收的可能路径与时间
## 10. 情景分析：保守/基准/乐观，各情景由哪些变量驱动（不机械给数字）
## 11. 推翻条件与领先指标：哪些证据会推翻本判断；未来 6–12 个月观察哪些指标
## 12. 对其他 Agent R1 结论的质疑（至少 2 条，点名 Agent 与编号）
## 13. 证据缺口与不确定性
```

## 检索纪律（R2 更严格）

- 本轮全体共享检索配额有限：**每个 Agent 最多 15 次 WebSearch**。先读 R1 备忘录与台账，只为填补关键缺口检索。
- 若检索被拒（配额用尽），立即停止检索，用已有证据完成稿件，并在第 13 节写明缺口。
- 其他纪律同框架文件：不编造 URL、数字、引文；检索摘要级来源如实标注；融资不等于需求，Logo 不等于付费，招聘广告不等于就业。
