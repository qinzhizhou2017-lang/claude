## 0. 一句话结论与置信度

需求真实且已有人付费，但钱流向既有平台：2025–2026 年被核实的 AI 安全初创全部由网络安全厂商收购，基础 Agent 身份已开始免费捆绑。主类别是网络安全行业的 T4 升级（N2–N3），不是独立 T1。个人最可进入的环节是权限基线与组合系统红队，适合安全或 IAM 背景者。置信度：中。

## 1. 它解决什么问题：因果链

**技术变化。** MCP 交由 Linux 基金会中立治理，公开服务器超过 1 万个 [A05-S020][A05-S021]，把模型接入企业系统的单点成本压得很低。与此同时，提示注入无法根除：厂商自己声明没有浏览器 Agent 能免疫注入 [A01-S050]，独立基准的无防御攻击成功率在 34%–77% [A01-S052]。

**原有任务如何变化。** 传统集成由工程师在开发时写死调用逻辑，用一个固定服务账号访问系统，访问边界在上线前就确定了。Agent 则在运行时根据自然语言上下文决定调用哪个工具，而上下文可能来自不可信的网页、邮件、工单。于是“谁在以谁的身份做什么”从开发期问题变成运行期问题。

**制造的新瓶颈。** 一是身份：Agent 用自己的身份还是代表用户行事，委托链如何追溯。二是权限：工具级、任务级、限时的最小权限如何设定。三是供应链：第三方 MCP 服务器和技能包可能被投毒或植入后门。四是验收：厂商公布的注入成功率不能直接搬到自己的威胁模型上。

**形成的付费活动。** 产品端有运行时防护（AI 防火墙、提示层过滤）、Agent 身份与治理 SKU、自动化红队；服务端有权限设计、组合系统红队、准入审计；岗位端出现“AI 安全工程师”“Agent 安全工程师”。支撑它们的主要是既有安全厂商的新产品线和企业安全团队内部的专长岗位，独立公司很少。

## 2. 性质判定

**主类别 T4（网络安全行业升级），次要属性 T3 雏形；新颖度 N2，其中工具投毒审计、Agent 委托链设计为 N3。**

不判 T1 的理由有三。【事实】第一，2025 年 4 月到 11 月，被核实的 AI 应用层安全初创（Protect AI、Prompt Security、CalypsoAI、Pangea、Lakera、SPLX）全部被网络安全或网络设备厂商收购，买方没有一家是云厂商或模型厂商 [A05-S044][A05-S049][A05-S046][A05-S047][A05-S048][A05-S051]。F5 明确表示，CalypsoAI 对其收入和经营业绩不构成重大影响 [A05-S046]，说明被收购方收入很小。第二，预算主要挂在既有安全预算下（见第 3 节）。第三，买方是 CISO，采购走既有安全平台合同。置信度：高（并购事实）/中（预算）。

不判 T5，是因为底层问题不会随模型进步消失。A01 的机制论证成立：注入防护效果取决于威胁模型，而威胁模型只有部署方能界定 [A01-S050][A01-S052]。权限越大，注入的潜在损失越大。

岗位层面，按 F-4 建制化标准：“AI 安全工程师”类职位已扩散到至少 8 家企业，并出现 Principal、Sr. Staff 等资深职级 [A05-S079][A05-S080]，满足“3 家以上企业”和“资深层级”两条；但没有证据显示它有独立汇报线或独立预算科目。【推断】它更像十年前的“云安全工程师”：在安全团队内部形成一个持久专长，而不是一个新的组织职能。所以岗位只给 T3 雏形。R1 把 K13 判为 T1 [A01 O6]，本稿下调为 T4：其中通用红队部分已被产品化（Zscaler 收购 SPLX 时把“自动化红队测试”并入平台 [A05-S051]）。

## 3. 谁使用、谁付费、谁批准预算；不购买的代价

使用者是平台工程、应用安全和 IAM 团队；付费方是企业安全预算；批准人是 CISO，涉及 AI 平台时由 CIO 或 AI 平台负责人共批。

【事实】预算结构只有小样本证据。Open Future Forum 2026 年 10 月调查：34% 的受访 CISO 有 AI 安全专项科目，35% 按项目逐案拨款，26% 从既有安全预算中切出，11% 没有 AI 安全支出；“Agent 访问”以 68% 列首要问题 [A05-S077]。各期样本只有约 45–151 人，机构背景不明，只能看方向。IDC 称全球企业计划 AI 投资中平均 16.7% 分配给 AI Agent 安全与治理 [A05-S076]，样本未披露。置信度：低–中。

需要特别区分：多个调查里“69% 的 CISO 把 AI 列为净新增投资首要方向”[A05-S074][A05-S075]，测的是“用 AI 做安全”，不是“为 AI 做安全”，不能拿来证明 Agent 安全预算。

**不购买的代价。**【事实】公开事件已经覆盖本方向的每一类风险：2025 年 5 月 GitHub MCP 被公开 issue 注入，Agent 把私有仓库代码泄露到公开 PR；2025 年 9 月官方命名空间下的 Postmark MCP 包被发现把所有外发邮件暗中密送给维护者 [A05-S072]（E5 汇编）；mcp-remote 的 CVE-2025-6514 在连接不可信服务器时可导致客户端远程代码执行，CVSS 9.4–9.6 [A05-S070][A05-S071]；OWASP 2026 年第三季度汇编记录了 Agent 绕过网络限制后找到公开凭证并加以分享的案例 [A05-S068]。【缺口】这些事件的经济损失没有公开数据，保险理赔也未检索。所以“不购买的代价”目前是可见但未量化的事件风险，还没有强制性的合规罚则。

## 5. 市场规模与需求增长

本方向能取得的 M1 只有一个锚点。【事实】Prisma AIRS 的 ARR 约 1.2 亿美元（M1b 合同口径），客户超过 800 家，一个季度内增长超过 2 倍 [A05-S058]。【推断】这已是独立可观测性工具 LangSmith ARR（1,200–1,600 万美元 [A05-S033]）的 7.5–10 倍（本文测算），说明安全类 AI 治理比可观测性更快形成付费；但这笔收入可能含 Protect AI 原有业务，且记在平台厂商账上。

并购对价不是需求（不属 M1），但能看出资本把价值押在哪里。本文测算（python）：已披露的 AI 应用层交易合计约 10.1 亿美元（Prompt Security 只计现金），身份层交易约 218–269 亿美元，前者只相当于后者的 3.8%–4.6%。【推断】资本认为，Agent 时代的控制点在身份与授权，不在提示层过滤。替代解释：CyberArk 的价格主要反映其既有特权访问业务，“AI 时代”只是并购叙事。置信度：中-低。

服务层没有任何 M1 或 M2 数据。下面只公开一个示意公式，供 R3 和 A11 替换参数：

> 外部服务支出 = N（已付费购买 AI 安全产品的企业数）× P（每客户产品年支出）× r（外部服务与产品支出之比）

参数：N 取 800（只算 Palo Alto 一家的客户，作下界）；P 取 15 万美元（1.2 亿 ÷ 800，为上限）；r 取 0.2–0.5（**无来源的假设**）。结果：每客户每年外部服务 3–7.5 万美元，仅这 800 家合计约 0.24–0.6 亿美元（本文测算）。这个数只说明量级很小、集中在大企业，不代表市场总量。

需求增长的领先信号是一致的：HackerOne 平台有效 AI 漏洞报告 2025 年同比 +210%，两年 +222%，系统提示泄露同比 +557% [A05-S091][A05-S090]；OWASP 在 2025 年底发布 Agentic Top 10，美国国家安全局据报道于 2026-05-20 发布 MCP 安全设计指导 [A05-S067][A05-S088]。

## 6. 收费方式、交付方式、成本结构与单位经济

产品端已形成三种收费方式：按用户计价并捆绑进套件（Agent 365 每用户每月 15 美元，E7 每用户每月 99 美元 [A05-S062]）；单独 SKU 订阅（Okta for AI Agents，未公开标价 [A05-S064]）；平台 ARR（Prisma AIRS）。【事实】基础能力正在零价化：Okta 的 Agent SSO 不额外收费 [A05-S065]，Entra Agent ID 对所有 Entra 客户可用 [A05-S060]。按用户而不是按 Agent 计价，说明厂商把 Agent 当作“用户的附属”来卖，避免 Agent 数量爆发后计价失控。

服务端的形态是固定价格评估、年度复测订阅和漏洞赏金。HackerOne 建议 AI 赏金最低支付为严重 5,000 美元、高危 2,000 美元 [A05-S092]；但全平台一年赏金合计只有 8,900 万美元 [A05-S090]，分给全球研究者。【推断】赏金适合用来积累公开记录，难以作为稳定收入。

单位经济方面，服务的成本几乎全是人力，工具大多开源；风险在于责任：一次漏检之后的追责。按第 5 节示意参数，一名独立顾问要达到 20–30 万美元年收入，需要 3–10 个持续客户（本文测算）。对中国个人而言，这类客户主要在海外，语言与签约主体是现实门槛。

## 7. 个人或小团队可切入的具体环节

| 环节 | 被平台默认配置吸收的可能 | 个人可进入性 | 理由 |
|---|---|---|---|
| 准入审计（MCP 服务器与技能包扫描、签名核验） | 高，2027–2028 年 | 中，单纯扫描属 T5 | 注册表签名与扫描会被平台内置（SPLX 已覆盖 MCP 服务器 [A05-S051]）；持久的是“准入政策加复审节奏” |
| 权限基线（工具到权限映射、委托链、限时授权） | 低 | 高（需 IAM 背景） | 平台提供机制，但哪个 Agent 能动哪类数据取决于客户业务，与角色工程同理 |
| 组合系统红队（Agent 加工具加数据加权限的业务逻辑滥用链） | 中，通用注入测试会被自动化 | 中-高 | 厂商数字与真实威胁模型脱节 [A01-S050][A01-S052]，买方需要独立复核 |
| 事件响应 | 高，归 MDR 与应急响应厂商 | 低 | 需要 7×24 值守、保险机构名录资格和取证能力 |

**安全或 IAM 背景者（3–6 个月可起步，本文推断）。** 需要达到的程度：读懂 MCP 授权流程（它基于 OAuth，CVE-2025-6514 就出在 OAuth 端点处理上 [A05-S070]）；能把 OWASP ASI02、ASI03 [A05-S067] 逐项映射到 Entra Agent ID、Okta for AI Agents 的具体配置；能设计 Agent 的限时授权与撤销流程。可以公开的作品：一份开源的“Agent 权限基线模板”（风险项、配置项、检查脚本三者对应），以及一两份脱敏的组合系统红队报告。变现路径是把它挂在既有 IAM 或渗透测试服务下销售，不单独开新品类。MCPA 认证 [A05-S023] 可作入门信号，其市场认可度没有数据。

**非安全背景工程师（6–12 个月，本文推断）。** 先补 Web 安全与身份认证基础，再搭建并攻击自己的 Agent。作品顺序：先在 HackerOne 上 1,121 个纳入 AI 的项目中提交有效报告 [A05-S091]，再给开源 MCP 扫描器贡献检测规则，最后争取一个 CVE。目标岗位是普通企业的“AI 安全工程师”：美国 5 个甲方岗基本薪酬中点的中位数约 20.7 万美元（本文测算，招聘广告不等于实际雇用）。中国薪酬和岗位数没有检索证据。

## 8. 进入者优势的来源及其可持续性

可持续的优势有三类。**客户特定知识**：权限基线要求理解业务流程和数据敏感度，平台默认配置给不出“财务 Agent 不能在月结周之外调用付款工具”这种规则。**独立性带来的信任**：厂商自报的注入成功率（1%）与第三方基准（73%）差异极大 [A01-S050][A01-S051]，买方有动机找非利益相关方复核。【推断】这与渗透测试长期作为独立服务存在、没有被安全产品吸收的逻辑相同（本轮未检索渗透测试市场数据，置信度低-中）。**公开记录**：CVE、赏金排名和开源规则库可以替代大公司背书。

不可持续的是信息差，例如“知道 MCP 有哪些已知漏洞”。OWASP 和 AAIF 正在把这类知识标准化 [A05-S067][A05-S025]。

## 9. 替代风险

【预测】主要有四条吸收路径。（1）身份默认化：Okta 免费 Agent SSO 与 Entra 全量可用已经发生 [A05-S065][A05-S060]，预计 2027 年基础 Agent 身份成为身份平台的标准功能，单独售卖的“Agent 身份咨询”会被压价。（2）红队自动化：通用注入测试已被并入 Zscaler、Palo Alto 等平台 [A05-S051][A05-S044]，预计 2027–2028 年“跑一遍通用攻击库”不再值钱。（3）注册表治理：AAIF 把正式治理与安全列为企业化重点 [A05-S025]，OWASP 把供应链列为单独风险项 [A05-S067]，预计签名、来源核验会在 2028 年前内置进主流注册表。（4）模型进步：如果第三方基准下的注入成功率也降到个位数，红队需求会收缩。失效情形是相反的：Agent 写权限普及得比防护快。

## 10. 情景分析

| 情景 | 驱动变量 | 对个人的含义 |
|---|---|---|
| 保守 | 平台默认配置足够好；无重大 Agent 事故；CISO 从既有预算拨款 | 只能以雇员身份进入甲方或厂商安全团队；独立服务局限于大企业 |
| 基准 | 产品集中到 5–8 家在位厂商；服务以“权限基线加年度组合系统红队”形态存续，挂在渗透测试或 IAM 咨询下 | 有安全或 IAM 背景者可做小型精品服务；非安全背景者经赏金和开源转岗 |
| 乐观 | 出现有可量化损失的重大 Agent 事故，保险或采购标准（如对接 OWASP 的 AIUC-1 [A05-S069]）要求第三方 Agent 测试 | 出现窄 T1 的独立测试与认证市场，先建立公开记录的个人与小团队受益 |

## 11. 推翻条件与领先指标

**会推翻本判断的证据**：有独立 AI 安全厂商在未被收购的情况下 ARR 超过 1 亿美元（推翻“T4、被吸收”）；样本过千的调查显示 AI 安全专项科目超过一半（推翻“预算挂在既有安全下”）；平台推出客户普遍接受的自动最小权限策略生成（推翻“权限基线不被吸收”）。

**未来 6–12 个月观察**：Prisma AIRS 的 ARR 与客户数，以及 CrowdStrike、SentinelOne 是否单列 AI 安全收入；Okta for AI Agents 是否公开标价；HackerOne 下一期 AI 类别的数据；OWASP 季度事件汇编的数量；MCP 相关 CVE 数；招聘网站上标题含“Agent Security”的职位数；中国信通院或全国网络安全标准化技术委员会是否发布智能体安全标准。

## 12. 对其他 Agent R1 结论的质疑

1. **A06（R1 第 6 节第 1 条，“吸收者至少包括网络安全厂商与 GRC 厂商”）**：前半句得到 E1/E2 证据支持，置信度高，6 起核实交易的买方全是安全或网络厂商。后半句证据不足：本轮唯一与 GRC 相关的是 ServiceNow 收购 Veza，只有 E5 来源 [A05-S054]。建议改为：吸收者是网络安全厂商（并购）和身份与办公套件厂商（免费捆绑），GRC 厂商待证。后者对个人服务的价格冲击更大。
2. **A01（F9 与 O6）**：“1% 对 73%”不是同一测试下的差距。前者是厂商内部自适应攻击，后者出自另一篇预印本的不同场景，而 1.29% 那个数是二次论文转述的系统卡 [A01-S050][A01-S051]。最终报告不应写成“1%–73% 的区间”，应写成“不同威胁模型下结果不可比”。这一差异恰恰支撑独立复核的需求；但 O6 判为 T1 不成立，产品层已被吸收，应为 T4。
3. **A12（H4 反方论证一，“被平台捆绑”）**：方向成立，但需要更精确。捆绑不等于不付费：Prisma AIRS 一年 ARR 约 1.2 亿美元，是单独计价的产品 [A05-S058]。准确的反方表述应是“独立厂商市场不成立，钱进入在位平台”，而不是“治理没有预算”。对个人而言，平台工具普及反而扩大了配置与复核的服务需求。
4. **A05 自身 R1（O1）**：R1 对“MCP 准入审计”给出“个人可进入性中-高”。本轮修正为：单纯扫描属 T5；持久的是权限基线与组合系统红队，而且主要适合有安全或 IAM 背景的人。
